# Game Design Document — LAST LIGHT: สัญญาณสุดท้าย

**สถานะ:** Design baseline สำหรับ prototype
**ประเภท:** 2D vertical survival shooter / arcade action
**Engine:** Godot 4.7.2
**ผู้เล่น:** 1 คน, PvE
**เป้าหมาย:** Windows PC และ Android
**Session เป้าหมาย:** 4–7 นาทีต่อรอบ

## 1. High concept

ผู้เล่นเป็นผู้ควบคุมป้อมปืนเคลื่อนที่ที่แนวล่างของจอ ฝูงสิ่งมีชีวิตจากรอยแยกบนท้องฟ้าบุกลงมาหา Beacon ที่ต้องปกป้อง ผู้เล่นยิงอัตโนมัติและขยับซ้าย–ขวาเพื่อจัดแนวกระสุน ขณะสะสมพลังจากการกำจัดศัตรู เมื่อเกจเต็มต้องเลือก:

- **Overclock:** ใช้พลังเพิ่มระดับอาวุธถาวรสำหรับรอบนี้ ทำให้รับมือฝูงระลอกถัดไปง่ายขึ้น
- **Pulse:** ใช้พลังทันที ปล่อยคลื่นผลัก/ทำลายศัตรูบริเวณแนวป้องกันเพื่อหยุดการ breach

การเลือกทุกครั้งแลกความปลอดภัยปัจจุบันกับกำลังยิงในอนาคต

## 2. Pillars

1. **อ่านสถานการณ์ได้ทันที:** ศัตรูมี silhouette, สีเตือน และ telegraph ต่างกัน; ผู้เล่นมองเห็นแนวที่กำลังจะ breach
2. **เล่นง่าย แต่ตัดสินใจมีน้ำหนัก:** ยิงอัตโนมัติและควบคุมแค่ตำแหน่งกับการใช้เกจ
3. **รอบสั้นและพลาดแล้วอยากเริ่มใหม่:** ทุกการเล่นให้ผลตอบรับชัด ไม่บังคับฟาร์มนาน
4. **ให้รางวัลกับการเล็งและจัดตำแหน่ง:** การยืนในแนวที่ถูกต้องยิงทะลุเป้าหมายหรือช่วยปิดหลาย lane ได้

## 3. Core loop

1. เริ่มภารกิจและดูคลื่นศัตรูที่กำลังลงมา
2. ขยับแนวปืนไปยัง lane สำคัญ; ปืนยิงเป้าหมายเหนือผู้เล่นอัตโนมัติ
3. กำจัดศัตรูเพื่อเติม **Resonance**
4. เมื่อเกจเต็ม เลือก Overclock เพื่อเพิ่มพลังระยะยาว หรือ Pulse เพื่อหยุดการรุกทันที
5. เอาตัวรอดจนหมดเวลาและกำจัดบอส
6. รับ Salvage ตามผลงาน; ปลดล็อกอาวุธ/รูปลักษณ์/บันทึกเรื่องราวระหว่างรอบ

## 4. กติกา MVP

- พื้นที่เล่นคงสัดส่วน **9:16**; กล้องมองลงในฉาก 2D และศัตรูเข้าสนามจากขอบบน
- ผู้เล่นเคลื่อนที่ตามแกน X ในแถบล่างของสนามเท่านั้น; ขอบซ้าย/ขวาจำกัดการเคลื่อนที่
- ปืนหลักยิงขึ้นด้านบนอัตโนมัติ โดยล็อกเป้าหมายที่อยู่ในแนวหรือเลือกเป้าหมายตามกติกาที่แสดงใน HUD
- ศัตรูที่ข้ามเส้นล่างสร้างความเสียหายให้ **Beacon Integrity** แล้วออกจากฉาก; เกมจบเมื่อ Integrity หมด
- ศัตรูที่ถูกกำจัดและเหตุการณ์สำคัญให้ Resonance; เกจเต็มแล้วคงเต็มจนผู้เล่นเลือกใช้
- Overclock เพิ่มระดับอาวุธของรอบปัจจุบัน (เป้าหมาย 3 ขั้นใน MVP); Pulse เป็นการใช้หนึ่งครั้งที่มีผลชัดและจำกัดด้วยเกจ
- หนึ่งภารกิจ MVP ยาวประมาณ 5–6 นาที มีช่วงเปลี่ยนจังหวะและบอสท้ายภารกิจ
- จบรอบแล้วให้ Salvage บางส่วนแม้แพ้ เพื่อให้ความล้มเหลวไม่ทำให้ความคืบหน้าหายทั้งหมด

**ค่าตัวเลขทั้งหมดเป็นค่าเริ่มต้นสำหรับ playtest** ไม่ใช่ balance ที่พิสูจน์แล้ว

## 5. ศัตรูและแรงกดดัน

| บทบาท | การเคลื่อนที่/สัญญาณ | บทบาทต่อการตัดสินใจ |
|---|---|---|
| Drifter | ลงตรงช้า, silhouette ใหญ่ | เป้าหมายฝึกเล็งและวัด DPS |
| Skitter | ลงพร้อมส่ายซ้าย–ขวา | บังคับให้ผู้เล่นคาดการณ์แนว |
| Dasher | หยุดส่งสัญญาณสั้น ๆ ก่อนพุ่งลง | สร้างเหตุผลให้เก็บ Pulse ไว้ |
| Bulwark | เคลื่อนที่ช้า ทนกระสุน | บังคับ Overclock หรือยิงต่อเนื่อง |
| Rift Warden (บอส) | เปลี่ยน phase และเรียกศัตรูสนับสนุน | ทดสอบการอ่านสัญญาณและบริหารเกจ |

ไม่ใช้ pathfinding ใน MVP: ศัตรูเคลื่อนใน lane/trajectory ที่กำหนดไว้ ความต่างมาจากจังหวะ, ความเร็ว, การส่าย และ telegraph

## 6. โครงรอบและความยาก

- 0:00–1:00 — สอนการจัดแนว, ศัตรูพื้นฐาน, เกจเริ่มชาร์จ
- 1:00–2:30 — เพิ่ม Skitter และ lane pressure; เปิดโอกาส Overclock ครั้งแรก
- 2:30–4:00 — Dasher/Bulwark มาเป็นชุดที่อ่านได้ ไม่สุ่มซ้อน telegraph
- 4:00–5:00 — ช่วงเร่งแรงกดดัน พร้อมช่วงพักสั้นให้ประเมินตำแหน่ง
- 5:00–6:00 — บอสและบทสรุปภารกิจ

WaveDirector ใช้ wave ที่ออกแบบเป็น data ไม่สุ่มแบบไร้ขอบเขต; RNG ใช้เพียงปรับ variation ภายในขอบที่ทดสอบแล้ว

## 7. Progression

### ระหว่างรอบ

- Resonance แลก Overclock หรือ Pulse ตามสถานการณ์
- อาวุธเริ่มต้นเพียงหนึ่งแบบ; prototype มีระดับอัปเกรดจำนวนจำกัดเพื่อบาลานซ์ง่าย
- เพิ่ม passive upgrade draft หลัง core loop สนุกแล้วเท่านั้น

### ระหว่างภารกิจ

- Salvage ใช้ปลดล็อกอาวุธ/skin/ข้อมูลเรื่อง ไม่เพิ่มค่าสถานะถาวรจนทำให้ผู้เล่นใหม่เสียเปรียบ
- บันทึกที่พบระหว่างภารกิจเปิดเนื้อเรื่องเพิ่ม ไม่บังคับอ่านก่อนเล่น
- ไม่มี hunger/thirst, base-building หรือ inventory ขนาดใหญ่ใน MVP; ไม่เพิ่ม survival chores ที่ไม่ช่วยการตัดสินใจยิง

## 8. UX, input และ accessibility

- **Windows:** A/D หรือปุ่มลูกศร = เคลื่อนที่, Space = Pulse, E = Overclock, Esc = pause; ปืนยิงอัตโนมัติ
- **Android:** ลาก/virtual stick บริเวณล่างเพื่อเคลื่อนที่, ปุ่ม Pulse และ Overclock แยกกัน; ปืนยิงอัตโนมัติ
- Action ใช้ชื่อเชิงเจตนาใน InputMap ไม่อ่าน raw key โดยตรง; รองรับ gamepad เป็นทางเลือก
- ปุ่มสัมผัสไม่ทับพื้นที่ศัตรูหรือ safe area; UI ยึด anchor/container และคง field 9:16
- สีไม่ใช่สัญญาณเดียว: เพิ่มรูปทรง ไอคอน และ animation telegraph
- ตัวเลือก: ลด shake/flash, ปรับเสียงแยกหมวด, ปรับขนาด UI; remap และปรับความไวเมื่อเริ่มทำ settings

## 9. เสียงและ game feel

- ทุกเสียงส่งผ่าน bus: Master, Music, SFX, UI, Ambience, Voice
- เพิ่มชั้นดนตรีเมื่อ threat สูง; ลด/พักชั้นดนตรีช่วงเตือนบอสและช่วงท้าย
- ยิงปกติใช้ feedback เบา; hit/เก็บ Resonance ใช้เสียง+ประกาย; Overclock ใช้เสียงและ animation ที่บอกว่าอัปเกรดสำเร็จ; Pulse ใช้ flash/shake/hit-stop แบบสั้นและลดได้
- feedback ต้องไม่บัง telegraph หรือทำให้เกิดอาการเวียนหัว; การสั่นมาจากกล้อง ไม่ย้าย collider ของ gameplay

## 10. เป้าหมายการทดสอบเบื้องต้น

ใช้เป็นสมมติฐานสำหรับ playtest ไม่ใช่คำรับรอง:

- ผู้เล่นใหม่เข้าใจการขยับ/ยิงได้ภายใน 15 วินาที โดยไม่ต้องอ่านบทสนทนา
- ผู้เล่นมองเห็นและเข้าใจความต่าง Overclock/Pulse ก่อนเจอเกจเต็มครั้งแรก
- ศัตรูตัวที่เร็วมีช่วงเตือนที่ผู้เล่นตอบสนองได้; ความเสียหายจาก breach ระบุได้ว่าเกิดจากอะไร
- รอบแรกของผู้เล่นใหม่ไม่ลงโทษจนหมดโอกาสเห็นระบบเลือกใช้เกจ
- ทดสอบภาระฉากเป้าหมาย 60 FPS บนเครื่อง Windows อ้างอิงและ Android ระดับกลางที่ทีมระบุ ก่อน lock ตัวเลขจำนวนศัตรู/กระสุน
- ตรวจ UI บน 9:16, 16:9 (แถบข้าง), จอความละเอียดต่ำ และ Android ที่มี safe area

## 11. Non-goals และ scope guard

- ไม่ทำ 3D gameplay, multiplayer, online backend, open world, base building หรือระบบ crafting ใน MVP
- ไม่สร้าง procedural level ก่อนที่ wave ที่ออกแบบมือจะสนุก
- ไม่ทำการซื้อขายเงินจริงหรือระบบสุ่มของแบบกาชา
- ไม่ทำ content จำนวนมากก่อนผ่าน vertical-slice gate ใน [ROADMAP.md](./ROADMAP.md)

## 12. คำถามค้างสำหรับ playtest

- ควรยิงเป้าหมายใน lane ปัจจุบันหรือเลือกศัตรูใกล้เส้นล่างก่อน: ทดสอบทั้งสองแบบ
- ควรมีการเล็งแบบกดค้างบนมือถือหรือไม่: ทดสอบหลัง auto-target baseline
- ระยะเวลา 5–6 นาทีและอัตราเกจเต็มเหมาะกับ session สั้นหรือไม่: วัดจาก session จริง
