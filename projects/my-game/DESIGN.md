# Kick Hero Arena — เอกสารออกแบบเกม

> เกมฟุตบอล 1v1 แต่ตลกและแสบ ในสไตล์ arena แบบ Head-Soccer: กำแพงล้อมสนามทุกด้าน บอลไม่มีทางออก แข่งแบบผู้เล่นคุม Hero 1 คน ผู้รักษาประตู Auto

## แก่นเกม (Core Loop)

1. บอลอยู่กลางสนาม — กระดิ่งขึ้น คุม Hero เตะ/แย่ง/ใช้สกิล เพื่อยิงเข้าประตูฝั่งตรงข้าม
2. ประตูได้ 1 คะแนน → บอลรีเซ็ตกลางสนาม
3. จบเมื่อเวลาหมดหรือคะแนนถึง N → ผู้ชนะคือผู้ยิงได้มากกว่า

## มุมมองสนาม (Camera)

- **Bird's Eye View (top-down)** — มองจากด้านบนทั้งสนาม (ไม่ใช่มุมข้าง)
- สนามแนวนอน 480×270 ทั้งจอ, ประตูอยู่ที่กำแพงซ้าย/ขวาครึ่งกลาง, GK ยืนเฝ้าช่องประตู
- บอลเลื่อนบนพื้นสนาม (ไม่มีโน้มถ่วง — top-down), เด้งกำแพงทุกด้าน, มีแรงเสียดทานทำให้วิ่งช้าลง

## สนาม (Arena)

- จากมุมมองข้าง (side view) 2D → **top-down (bird's eye)**
- มุมมองจากด้านบน — บอลเลื่อนบนพื้น ไม่มีโน้มถ่วง (gravity_scale = 0)
- **กำแพง 4 ด้าน** — บอลชนแล้วเด้ง ไม่มีการออกนอกสนาม (throw-in ไม่มีในเกมนี้)
- ประตูฝั่งซ้าย/ขวาที่กำแพง **เจาะช่องไว้ตรงกลาง** มี **ผู้รักษาประตู (GK) อัตโนมัติ** ยืนเฝ้าช่อง
- บอลมีแรงเสียดทาน (linear_damp) ทำให้วิ่งแล้วช้าลงเหมือนพื้นสนามจริง

## ตัวละคร: Hero

Hero แต่ละตัวมี **สกิลประจำตัว** + ท่าพิเศษเฉพาะ (self expression) — คนถนัดตัวไหนก็เลือกตัวนั้น

| Hero | สกิลเด่น | ฟีลการเล่น |
|---|---|---|
| Pow (ลูกตะพานห่านกำาลังยิง?) | **ยิงแรงไกล** — จ่ายบอลระยะ + ผ่านกำแพงคน | เล่นไกล, ปลอดภัย |
| Pierce | **ยิงทะลุ** — บอลทะลุตัวคนยืนกั้น (แต่ไม่ทะลุ GK/GK อ่านยาก) | หลอกโต้แต่แรง |
| Zoomie | **วิ่งเร็ว** — คุมบอลติดอยู่ทุกซอก  ขโมยก่อนคู่แข่งเห็น | ลากเชือกยืดแย่ง |
| Wabby | **วาปได้** — เทเลพอร์ตข้ามบอล/คู่ต่อสู้ (cooldown สั้น) | มือเร็ว พริบตา |
| Chomp | **พุ่งชน** — ชาร์จตัวพุ่งบอลเต็มแรง บอลแตกเต็น | แกี่ตัวโหด |
| Stealer | **แย่งบอลเก่ง** — วงแย่งบาลบาลรอบตัวกว้าง | ผู้รักษาสำรอง, ทำเกมทลาย |

(ชื่อ/จำนวนชุดแรกตั้งเพื่อทดสอบ — เดี๋ยวเกมหน้าจะปรับตาม feedback)

## การควบคุม (ควบโดย skill: input-systems)

- ผู้เล่น 1: **WASD วิ่ง 8 ทิศ (top-down), C เตะ/แย่ง, V สกิลพิเศษ, Space เร่งความเร็ว (Sprint), X ไอเทม (เตรียม)**
- ผู้เล่น 2: **ลูกศร วิ่ง 8 ทิศ, K เตะ/แย่ง, L สกิลพิเศษ, Shift Sprint, J ไอเทม (เตรียม)**
- ทิศเล็ง (aim) = ทิศที่กำลังกดวิ่งล่าสุด — เตะไปทางนั้น

### ระบบครองบอล (possession) — หัวใจของเกม

- บอล "ติดตัว" — เดินชนบอลว่างก็ครองได้ทันที บอลลอยติดที่ตำแหน่งหน้าตัว (aim × 11px)
- เตะ C/K = กับบอลตัวเองคือ "ยิง", กับบอลใคร (ลอยกลางหรือของคนอื่น) คือ "แย่ง"
- **แย่งสำเร็จ** → เจ้าของเดิม "สะดุด" (stun 0.45 วิ — วิ่งช้าลง 0.55×) บอลหลุดนุ่ม ๆ กระเด็นไปทางผู้แย่ง
- หลังเตะออก มีล็อก 0.35 วิ ไม่ให้ตัวไหนครองซ้ำทันขัด (กันการแตะบอลเด้งกลับมาครองดื้อ ๆ)
- Sprint (Space/Shift) = แถบสไตมิน่า: เร่ง ×1.75 จนแถบหมด (drain 0.85/s, regen 0.55/s) — ใช้เข้าแย่งบอลและเลี้ยงหลบ; ตอนสะดุดห้าม sprint

## ระบบพิเศษ

- **ไอเทมพิเศษ:** โผล่บนสนามช่วงเกมมุมกลาง (ครบวงเวลา — ใครแตะก่อนได้ก่อน) เช่น โรเลิ่ลลิงเก็ต, ตัวเร็ว, บอลหนัก, อำพราง
- **ท่าพิเศษ Hero (Ultimate):** เก็บเกจจากการแตะบอล/แย่งบอล — เมื่อเต็มปลดล็อกท่าเดโมพิเศษ
- **GK อัตโนมัติ "คอนกรีตแต่มีความผิดพลาดมนุษย์":** ยืนล็อกเส้น (x=14/466) ตามบอลแกน y + อ่านลูกยิงเข้าเส้นแบบ predictive (หน้าต่างสั้น 0.45 วิ + ค่าเพี้ยนอ่าน ±16px + ความเร็ว 100px/s) — เซฟรวดเร็วได้ แต่อ่านดีมีผิดพลาดบ้าง เลยยิงมุมบน/ล่างหนี GK ผ่านได้** (GK ล็อกแกน x ยืนบนเส้นเสมอ); **ประตูนับเฉพาะบอลว่าง (โดนเตะเข้าไป) — เดินบดบอลติดเท้าทะลุประตูไม่นับ**

- **ART v2 — สไตล์ 2D นุ่ม (soft 2D):** วาดใหญ่แล้วย่อด้วย LINEAR filter — Hero/GK 48×64 ยืนเต็มตัวมองด้านข้าง (base หันขวา + `flip_h`), บอล 40×40, สนาม field 480×270 — ขอบนุ่มไม่หยักแบบตารางพิกเซล (ไม่ใช่ pixel art)
- จอฐาน 480×270 logical (canvas_items stretch, window 1440×810)
- ตัวละครหน้าตาต่างกัน: P1 เสื้อแดงผมสั้นดำ / P2 ผมยาวทองชุดน้ำเงิน / GK เหลืองส้มถุงมือขาว

### Sprite ชุดเดิม (pixel art 16×16 — เลิกใช้, เก็บไว้อ้างอิง)

- สร้างด้วย `create_image_pro_flash` (pixellab MCP) ขนาด 32×32, `view "high top-down"`, หันหน้าเข้าหาผู้เล่น (south-facing) — รูปแบบเดิมใช้สูตรหมุน `sprite.rotation = aim.angle() + PI/2` (ART v2 เปลี่ยนเป็น flip_h แล้ว)
- ย่อ 32→16 ด้วยกฎ "สีเสียงข้างมากต่อบล็อก 2×2" (majority vote ระวังคมกว่า averaging)
- กฎรีเพ้นแดง→ฟ้า: จำแนกสีชุดแดงด้วยเงื่อนไข `R > G+50, R > B+40, G-B < 30` (ตัดสีเนื้อออก) → สว่าง→`#4d6dbe`, เงา→`#33538e`
- ต้นฉบับ/ของเก่าเก็บใน `assets_legacy/` (มี `.gdignore` กัน Godot import)
- **ข้อควรจำ pixellab:** เช็ค `get_balance` ทุกครั้งก่อน generate — ตอนนี้ทรัยอลคือ 40 generations/วัน และโควต้าหมดแล้วให้หยุด (ใช้ pixelart-mcp ฟรีแทนจนกว่าโควต้ารีเซ็ตวันถัดไป)

### BALANCE7 (2026-10-28) — ปลุกกลไก "อ่านผิด" ของ GK ให้มีชีวิต (misread 11→14) ✅

**วิธีเทสต์:** แมตช์เต็ม headless `--quit-after 20000` (เครื่องนี้ ~150fps — 6000 ครอบแค่ ~40 วิ ไม่จบแมตช์) + วิเคราะห์ log `[ARENA] GOAL` / `MATCH END`

**ผลทดลอง (แก้ทีละหัว เทียบ baseline):**

| รอบ | ตัวแปร | easy | normal | hard |
|---|---|---|---|---|
| baseline | — (cap 1.45 / track 75 / misread 11) | 0:0 (64 SAVE) | 0:0 (67) | 0:1 (68) |
| iter 1 | dive cap 1.45→1.15 | 0:0 | 0:0 | 0:0 ❌ revert |
| iter 2 | track_speed 75→60 | 0:0 | 0:0 | 0:1 ❌ revert |

**ข้อค้นพบ (เปลี่ยนโมเดลการจูน GK):**
- ประตูในเกมนี้ **ไม่มาจากการยิงมุม** — ลูกเฉียงจากไกลตัดระนาบ GK (x=14) ใกล้กลางปากประตูเสมอ (เรขาคณิตระนาบหักมุมยิง) และรัศมีบล็อค GK (hitbox 12×20 + บอล r=7 ≈ 17px + dive cap×0.20s ≈ 21.75px) ปิดปากประตูทั้งช่อง (มุมไกลจากกลางแค่ ±27px) → การลด dive cap / track_speed ยอดไม่ขยับเลย (ผล = baseline เป๊ะทั้ง 2 รอบ)
- ประตูจริงมาจาก **scramble บอลติดขัดที่เส้นประตู** (CLEAR ผลักบอลชน GK/เสาแล้วบี้หลุดหลังแนว — พิสูจน์จาก log ประตู hard t≈25s) + **จังหวะ GK ไดฟ์อ่านผิด**
- หัวจูนที่ใช่จึงเป็น `misread`: เดิม ±11px < threshold ~13–17px ที่ต้องเบี่ยงจึงจะเสียประตู → กลไก "อ่านผิดแบบคนจริง" ที่ออกแบบไว้**ตายตั้งแต่ไม่เคยทำงาน** เพิ่มเป็น ±14 ทำให้กลไกมีชีวิต (easy ได้ 2 ประตูจากจังหวะอ่านผิดจริง)

**ตัวเลขที่รับไว้:** easy ~2 ประตู/แมตช์, normal ~0.5 ประตู/แมตช์ (2 ใน 4), hard ~1 ประตู/แมตช์ — normal ยังต่ำกว่าเป้า 1–2/แมตช์ ถ้าอยากเพิ่มอีกให้ขยับ `misread 15–16` (ค่าเดียวใน gk.gd)

**อื่น ๆ ในรอบนี้:** แก้ docs/HANDOFF.md คำสั่งเทสต์ `--quit-after 6000→20000` พร้อมเหตุผล

### BALANCE8 (2026-10-28) — GK เป็น "เมโทรนอม" (คำสั่งดีไซน์: ประตูเยอะจากฝีมือ/จังหวะ) ✅

**เปลี่ยนแนวคิด:** เกมสนุกที่จำนวนประตู — GK **ไม่อ่านบอล ไม่ไดฟ์ ไม่มีการอ่านผิดอีกต่อไป** ขยับขึ้น-ลงตามแนวประตูด้วยจังหวะคงที่ เหมือนกันทั้งสองฝั่ง ทุกโหมด easy/normal/hard — ผู้เล่นอ่านจังหวะแล้วยิงตอน GK อยู่ไกลมุมตรงข้าม = ประตู, เซฟเกิดเฉพาะลูกยิงตรง ๆ ที่ชนตัว GK พอดี (โชคในการยิงยอมรับได้)

**gk.gd เขียนใหม่:** ลบ dive/misread/predict_lead/track_speed ทั้งชุด → ตำแหน่งเป็นฟังก์ชันของเวลา `ideal_y = mid + amp×sin(2πt/T)` กับ `patrol_period 4.0` วิ + servo วิ่งตามตำแหน่งอุดมคติ (โดนบอล/กำแพงดันเฉ แล้วกลับเข้าจังหวะเอง, cap `patrol_speed_max 90`); นาฬิกา `_t` ทั้งสองฝั่งนับเท่ากัน → จังหวะตรงกันเป๊ะ; คง `_punch_clear` (กันบอลแช่, headless) + log `[GK] SAVE/CLEAR` เดิม

### BUGFIX ร้ายแรง (2026-10-28) — root-position shake ตรึง RigidBody บอลนิ่งทั้งเกม ✅

**อาการ:** v2 test ทุกโหมด 0:0 บอลแช่นิ่ง (เวอร์ชันเก่าก็พอได้ประตู) — frame-log พิสูจน์: บอล `pos=(162.504181, 120.380585)` **ซ้ำเป๊ะหลายเฟรม** ทั้งที่ `v=(-262, -77)` — physics integration ไม่ทำงานเลย

**ต้นตอ:** เพิ่มเขย่าจอตอนประตูด้วยการเขียน `position` ของ root `Arena` (Node2D) ทุกเฟรม → ทุกเฟรม engine ดัน transform ล่าสุดของ node ทั้ง subtree กลับเข้า physics server → **RigidBody (บอล) ถูกตรึงกลับที่เดิมตอน integrate** (CharacterBody hero/GK ไม่กระทบ — ขยับด้วย node เอง)

**แก้ถูกทาง:** เขย่าผ่าน **`Camera2D.offset`** (`$Cam` node ใหม่ใน arena.tscn) — กล้องขยับ โลก/ฟิสิกส์ไม่โดนแตะเลย + ลบ code เขย่า root ทิ้ง

> **กฎเหล็ก:** ห้ามเขียน `position`/`transform` ของ root ที่มี RigidBody ลูกหลานทุกเฟรม — เขย่าจอใช้กล้องเท่านั้น
